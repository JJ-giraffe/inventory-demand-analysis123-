# 零售库存覆盖与补货优先级分析

以 SQL 和 Power BI 展示从需求统计、库存诊断到补货建议的完整思路。所有数据均为人工构造的教学数据，不代表真实企业、预测准确率或业务收益。

## 业务问题
哪些商品需要优先补货？哪些商品占用资金？没有近期销售的商品如何处理？

## 快速运行
安装支持 node:sqlite 的 Node.js 22.13+，在项目目录执行：
```sh
node scripts/run.cjs
```
无需额外依赖。程序在内存中建库、导入 CSV、执行 SQL、核对预期结果并导出 outputs/inventory_analysis.csv。脚本会覆盖该导出文件。Power BI Desktop 可直接导入结果 CSV。

## 数据与口径
- 快照日期：2026-10-01；需求窗口：2026-09-01 至 09-30，固定 30 个自然日。
- products：每个 SKU 一行，库存为快照库存，成本单位为示例人民币元，交期单位为天。
- sales：日期与 SKU 联合唯一，共 180 行；缺失销售行按零处理，真实业务需先判断是否漏数。
- 日均需求 = 30 天销售件数 / 30；覆盖天数 = 库存 / 日均需求。
- 零需求的覆盖天数为空，不能解释为零天；先分类 NO_DEMAND，再处理缺货和补货。
- 目标覆盖 = 交期 + 7 天缓冲；建议补货 = 向上取整 max(0, 日均需求 × 目标覆盖 − 现有库存)。
- 低于交期为 URGENT；低于目标为 REORDER；大于 60 天为 OVERSTOCK；边界等于目标为 HEALTHY。

## 结果预览
|SKU|覆盖天数|分类|建议补货件数|
|---|---:|---|---:|
|A|10|REORDER|40|
|B|2.5|URGENT|116|
|C|150|OVERSTOCK|0|
|D|空|NO_DEMAND|0|
|E|0|STOCKOUT|60|
|F|14|HEALTHY|0|

库存金额合计 10,500 元；需要补货的 SKU 共 3 个，建议总量 216 件。详见 [分析结论](docs/findings.md)。

## 项目结构
- data/：商品与每日销售示例数据
- sql/01_schema.sql：约束和表结构
- sql/02_analysis.sql：CTE、LEFT JOIN、聚合、NULLIF 与 CASE WHEN 分类
- scripts/run.cjs：运行和结果核对
- outputs/：可直接展示及导入 Power BI 的结果
- docs/power-bi.md：报表制作步骤及度量值
- docs/resume.md：简历描述与面试讲解

## 限制
历史销售只是需求代理；缺货会压低观察销售。本例未考虑在途、预留、最小起订量、季节性及交期波动。7 天缓冲是演示参数，并非统计安全库存。零需求商品需要人工确认后再决策。本仓库目前交付 SQL 与结果数据、Power BI 搭建说明，尚未提供 PBIX 或真实报表截图。
